# 2026-08-30 工作日志

## 二维码相册清理 App（QRCodePicClean）

从零开发了一个安卓 App（Java），主界面一个按钮，点击后扫描相册所有图片，用 ZXing 尝试识别二维码，识别成功即删除。已成功构建出 APK。

### 关键实现点
- **权限分级**：Android 13+ 用 `READ_MEDIA_IMAGES`；10~12 用 `READ_EXTERNAL_STORAGE`；9 及以下再加 `WRITE_EXTERNAL_STORAGE`（清单里用 maxSdkVersion 精确限定）。
- **设置跳转**：永久拒绝权限时弹窗，走 `Settings.ACTION_APPLICATION_DETAILS_SETTINGS` 跳应用详情页。
- **删除策略**：Android 11+ 用 `MediaStore.createDeleteRequest()` 走系统确认对话框（注意：返回的是 `PendingIntent`，不是 `Intent`，要用 `startIntentSenderForResult(pi.getIntentSender(), ...)`）；10 及以下用 `contentResolver.delete()` + `File` 兜底（DATA 列取路径）。
- **扫码**：`QRCodeScanner` 用 `RGBLuminanceSource` + `HybridBinarizer` + `MultiFormatReader`（POSSIBLE_FORMATS=QR_CODE, TRY_HARDER），解码前按 inSampleSize 降到 MAX_DIMENSION=2048 防 OOM。

### 构建环境与踩坑
- 本机无 Gradle/Android Studio，需手动下载 Gradle 8.7 到项目 `.tools/`。
- **Windows curl 下载 SSL 报 `CRYPT_E_NO_REVOCATION_CHECK`**，需加 `--ssl-no-revoke` 跳过吊销检查。
- 组合：Gradle 8.7 + AGP 8.4.2 + compileSdk 35（用已装的 android-35 平台）+ build-tools 34.0.0 + JDK 21。
- 踩坑1：Kotlin 依赖冲突（kotlin-stdlib 1.8.22 vs 旧 kotlin-stdlib-jdk7/8 1.6.21 重复类）→ `configurations.all { resolutionStrategy.eachDependency { kotlin 组强制 1.8.22 } }`。
- 踩坑2：`gradle wrapper` 生成时校验分发 URL 失败 → 加 `--no-validate-url`。

### 产物
- APK：`QRCodePicClean-v1.0-debug.apk`（3.5MB，包名 com.example.qrcodepicclean，minSdk 21 / targetSdk 34）。
- 已生成 Gradle wrapper，`gradlew assembleDebug` 可直接重建。
